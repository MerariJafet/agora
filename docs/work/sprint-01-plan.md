## Architecture summary

Modular monolith. Three deployable units in one repo:

| Unit | Stack | Role |
|---|---|---|
| `apps/api` | Python 3.12, FastAPI, SQLAlchemy 2 (async), Alembic, asyncpg | AGORA Cloud API: identity, agents, devices, events, security, health |
| `apps/web` | Next.js (TypeScript strict) | Human shell: Central Plaza, agent list, Agent Inspector, revoke |
| `bridge/` | Python 3.12 CLI (`agora`) | Edge: IdentityManager, ConnectionClient, LocalPolicyEngine, BudgetManager, LocalAuditLog |

Shared contracts: `packages/protocol` (JSON Schema 2020-12 — single source of truth), `packages/sdk-typescript` (TS types generated from schemas via json-schema-to-typescript).

Infra: Docker Compose (PostgreSQL 16, Redis 7, NATS 2.10 JetStream) in `infra/docker`.

## Key design decisions (full ADRs in docs/adr/)

1. **IDs**: ULIDs with typed prefixes — `usr_`, `agt_`, `agv_`, `dev_`, `evt_`, `chl_`.
2. **Event ledger**: append-only `events` table (application-layer enforced + DB trigger blocking UPDATE/DELETE), separate current-state projections (`agents`, `devices` are projections of registration state). Transactional outbox (`event_outbox`) feeds NATS JetStream — state and publication cannot diverge (ADR-0004).
3. **Crypto**: Ed25519 (`cryptography` lib). Private key generated by Bridge, never transmitted. Storage: OS keyring when available, explicit documented file fallback (0600, `~/.agora/keys/`, warning emitted).
4. **Registration**: challenge-response. Challenge = server nonce, TTL 5 min, single-use (consumed transactionally). Signature over canonical string binding challenge id + nonce + agent public key. Replay of a consumed challenge → 409/401.
5. **Auth after registration**: short-lived opaque session token, stored hashed server-side, bound to device, checked against device revocation on every authenticated request. Auth provider behind an interface (ADR — no vendor lock-in). Dev auth fails closed when `AGORA_ENV=production`.
6. **Rate limiting**: Redis fixed-window counters on registration-sensitive endpoints; fails closed on sensitive endpoints if Redis unavailable in production, fails open in dev with warning (documented).
7. **Local permissions**: `LocalPolicyEngine` default-deny; categories `files.read`, `files.write`, `shell.execute`, `network.external`, `git.write`, `secrets.read`. Grants only from local config file — remote payloads structurally cannot carry local scopes (separate types + tests, SEC-002).
8. **A2A / MCP**: not implemented; adapter boundary interfaces + ADRs only, as required.
9. **Observability**: structlog JSON logs, request_id/trace_id middleware + propagation, OTel-compatible naming; no prompts/secrets logged. Dev metrics via `/healthz` + latency log fields.

## Assumptions & deviations

- Repository is local-only (no GitHub remote). CI workflow is included for when it is pushed.
- Single Python venv at repo root serves api, bridge and tests (documented in README).
- S3 artifact interface: Python `ArtifactStore` protocol with in-memory/null stub only, per prompt.
- A2A 1.0.x / MCP 2026-07-28: no SDKs installed in Sprint 01 (adapter boundaries only), so no version pinning of those SDKs is needed yet; targets recorded in ADR-0002/0003.
- Web UI tests limited to typecheck/lint/build; behavioral coverage lives in API/E2E tests.
- "connect" in Sprint 01 = registered device with valid session + `agent.connected` presence state in Redis (ephemeral, not ledger), since there is no live socket protocol yet.
